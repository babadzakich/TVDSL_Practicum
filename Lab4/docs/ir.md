# Формат IR и API Lab4

## Представление

IR — типизированный трехадресный код без SSA. Параметры, локальные переменные и результаты функции представлены изменяемыми слотами (`ValueId`); каждое вычисление получает собственный временный. Одно определение слота может перезаписывать предыдущее. Идентификаторы временных и блоков назначаются детерминированно. IR не зависит от времени жизни AST.

Тип `IrType` переиспользует `funny::TypeKind` (сейчас `int` и `int[]`). Операнд — либо ссылка на слот/временный (`ValueRef`), либо непосредственное целое (`int64`, интерпретируемое по правилам 32-битного IR). У каждой инструкции есть позиция исходника, списки `defs` и `uses`, операнды и, если применимо, имя вызова или предикат.

### Инструкции

| Текст | Назначение |
| --- | --- |
| `%t = const N` | записать целую константу |
| `%d = copy X` | копировать операнд в слот |
| `%d = neg X` | унарный минус |
| `%d = add/sub/mul/div X, Y` | арифметическая операция |
| `%d = load_element %array %index` | чтение элемента массива |
| `%array = array_set %array %index %value` | обновление массива с записью нового значения в слот массива |
| `%d... = call name(args...)` | вызов; назначения результата соответствуют возвращаемым значениям |
| `assert predicate`, `assume predicate` | контрактные проверки/предположения |

Блок заканчивается ровно одним терминатором: `jump bN`, `branch predicate, bT, bF` или `return values...`. У блока также хранятся вычисленные `successors`, `predecessors` и, для тела цикла, инвариант. Ветвления, циклы и вычисления условий отображаются на обычные блоки и инструкции; арифметические выражения условий вычисляются до `branch`.

Арифметика IR имеет 32-битное знаковое представление и сложение, вычитание, умножение с переполнением по модулю `2^32`. Деление на ноль и выход за границу массива являются trap. Для `INT_MIN / -1` используется результат `INT_MIN`. Потенциально аварийные операции, вызовы, массивные операции и `assert`/`assume` не удаляются DCE.

Логические формулы, предусловия, постусловия и инварианты хранятся как типизированные деревья предикатов. Они не превращаются в выполняемый код и сохраняются при оптимизациях.

## Текстовый формат

Вывод `funnyir` содержит отдельные секции `IR before optimizations` и `IR after optimizations`; каждая перечисляет функции, виртуальные значения с типами и классами, блоки с предшественниками/преемниками, инструкции и терминатор. `%name` обозначает слот, `%tN` — временный, `bN` — метку блока. Суффикс `@line:column` указывает исходную позицию.

Пример:

```text
function f(x: int) returns (r: int) {
  values:
    %x: int [parameter]
    %r: int [return]
    %t0: int [temporary]
b0:  ; preds=[] succs=[]
  %t0 = add %x 2 @2:7
  %r = copy %t0 @2:3
  return %r
}
```

После секций печатаются `instructions_before/after`, `values_before/after`, `temporaries_before/after`, `colors` по каждой функции и `module_colors` — максимум цветов среди функций. `values` — объявленные слоты плюс используемые временные, `temporaries` — используемые временные. Цвета назначаются жадно отдельно каждой функции.

## JSON v1

`--json` печатает один JSON-объект:

```json
{
  "schema_version": 1,
  "before": { "schema_version": 1, "declaration_order": [], "formulas": [], "functions": [] },
  "after": { "schema_version": 1, "declaration_order": [], "formulas": [], "functions": [] },
  "metrics": { "functions": [], "colors": 0 }
}
```

IR-модуль содержит исходный порядок объявлений, формулы и функции. Функция включает имя, `entry`/`exit`, параметры, возвращаемые значения, контракты, значения и блоки. Блок содержит инструкции, терминатор, CFG-дуги и инвариант. Инструкция сериализуется с `op`, исходной позицией `pos`, массивами ID `defs`/`uses`, `operands`, `callee`, `predicate`. Операнд — объект `{ "value": id }` или `{ "int": n }`. `schema_version` равен 1 как у обертки, так и у IR-модуля.

Метрики функции: `instructions_before`, `instructions_after`, `values_before`, `values_after`, `temporaries_before`, `temporaries_after`, `colors`; итоговый `colors` — максимум по функциям. DOT графы выдаются отдельными файлами, а не включаются в JSON.

## Оптимизации

Три локальные оптимизации включены по умолчанию и настраиваются флагами CLI:

1. **Распространение констант** внутри базового блока, с инвалидированием значения после определения слота.
2. **Алгебраические упрощения и свертка констант**: безопасные тождества (`x+0`, `x-0`, `x*1`, `x*0`, `x/1`), двойное отрицание и вычисление операций над константами с 32-битной семантикой. Деление на ноль не сворачивается.
3. **Локальный DCE** до неподвижной точки. Удаляются неиспользуемые инструкции без наблюдаемых эффектов; вызовы, деление, загрузка/запись массива, проверки и предположения сохраняются.

CFG не меняется, межблочные преобразования и CSE не входят в эту реализацию. В тестах отдельный интерпретатор IR сравнивает результат и trap до/после оптимизаций.

## Живость и граф конфликтов

`analyze_liveness(const IrFunction&)` вычисляет `live_in`/`live_out` фиксированной точкой по CFG. `build_interference_graph(...)` добавляет ребра при одновременной живости значений, включая параметры. `greedy_color(...)` обрабатывает вершины по убыванию степени, при равенстве — по ID, используя цвета с нуля. Это метрика и основа для будущего распределения регистров; выделение реальных регистров и spill-код здесь не выполняются.

## C++ API

Заголовки находятся в `Lab4/IRLIB/Include`:

```cpp
funnyir::IrModule funnyir::lower(const funny::Module&);
void funnyir::optimize(funnyir::IrModule&, const funnyir::OptimizationOptions& = {});
std::string funnyir::print_ir(const funnyir::IrModule&);
std::string funnyir::print_ir_json(const funnyir::IrModule&);
std::string funnyir::print_cfg_dot(const funnyir::IrFunction&);
funnyir::LivenessResult funnyir::analyze_liveness(const funnyir::IrFunction&);
funnyir::InterferenceGraph funnyir::build_interference_graph(
    const funnyir::IrFunction&, const funnyir::LivenessResult&);
funnyir::Coloring funnyir::greedy_color(const funnyir::InterferenceGraph&);
std::string funnyir::print_interference_dot(
    const funnyir::IrFunction&, const funnyir::InterferenceGraph&, const funnyir::Coloring&);
```

`funnyir` — библиотечная CMake-цель, исполняемый файл называется `funnyir`. Поля IR-модели определены в `IR.h`; графы и текстовые представления можно передать последующему этапу генерации кода.
