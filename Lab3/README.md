# HW3. Семантические проверки и типы Funny

Семантический анализатор языка Funny (`docs/funny.ru.md`) на C++23 поверх PEG-парсера HW2. Он строит таблицы
символов, проверяет имена и типы, выводит типы локальных переменных без аннотации (бонус) и выдаёт
**аннотированный AST**: тип у каждого выражения, вид символа у каждой переменной, выведенные типы локальных.
Ошибки печатаются с позициями, и анализ не останавливается на первой ошибке.

- Формат аннотированного AST и C++-API: [`docs/ast.md`](docs/ast.md)
- Отчёт о типах, правилах и ограничениях: [`REPORT.md`](REPORT.md)
- Описание языка: [`docs/funny.ru.md`](docs/funny.ru.md)

`ParserLIB/` — копия парсера HW2 (ветка `lab2-peg-parser`). Изменения в ней: в `Ast.h` добавлены поля-аннотации
(`Expr::type`, `VarRef::kind`, `LocalDef::inferred`), печать дерева и JSON выводит их, `Overloaded.h` перенесён в
`Include/`, чтобы им могла пользоваться SemaLIB. Грамматика и разбор не менялись.

## Сборка и тесты

Нужны CMake ≥ 3.25, компилятор с C++23 и GoogleTest (системный пакет или `conan install . --build=missing`).

```sh
cmake -S . -B build -G Ninja
cmake --build build
ctest --test-dir build --output-on-failure
```

`ctest` запускает три проверки: `funnysema_unit` (gtest: таблицы символов, типы, вывод типов, инициализация,
печать, эталоны, мутации), `funnysema_cases` (`funnycheck test` — эталоны из `tests/`) и
`funnysema_missing_file` (код выхода и сообщение для несуществующего файла).

## Запуск

```sh
./build/SemaMain/funnycheck [--json] [FILE]        # аннотированный AST в stdout, ошибки в stderr; без FILE — stdin
./build/SemaMain/funnycheck symbols [FILE]         # таблицы символов после проверки
./build/SemaMain/funnycheck test [--bless] [DIR]   # эталонные тесты (DIR по умолчанию tests)
```

Коды выхода: `0` — успех, `1` — синтаксические или семантические ошибки (или проваленные тесты), `2` — ошибка
использования или ввода-вывода (`не удалось открыть '<path>'`). При любой ошибке AST не печатается; при
синтаксических ошибках семантика не проверяется (печатаются только они, как в HW2).

## Поддерживаемые конструкции и типы

Поддерживается весь язык, который разбирает HW2: функции (несколько возвратов, `requires`/`ensures`/`uses`),
формулы, все операторы (`=`, `a[i] = v`, кортежное присваивание, `if`/`else`, `while` с `invariant`, блоки,
`assert`, `assume`), выражения, условия и предикаты с кванторами и ссылками на формулы.

| Тип | Где встречается |
|---|---|
| `int` | переменные, выражения, индексы, результат `length` и `a[i]` |
| `int[]` | переменные, параметры и результаты функций |
| `bool` | только условия и предикаты (переменных типа `bool` в Funny нет) |
| кортеж `(T1, ..., Tn)` | результат функции с n ≥ 2 возвратами; допустим только в кортежном присваивании |
| функция `(T...) -> R` | функции модуля и встроенная `length: (int[]) -> int` |
| формула `(T...) -> bool` | формулы модуля; используются только в предикатах |

Неявных приведений и перегрузок нет (в Funny их нет): все типы должны совпадать точно. Правила типизации — в
[`REPORT.md`](REPORT.md).

## Проверки

**Имена и области видимости (таблицы символов).**

- Глобальная область: встроенная `length`, функции и формулы модуля (одно пространство имён). Порядок объявлений не
  важен: можно вызывать функции, объявленные ниже, и рекурсивно.
- Область функции: параметры, возвраты, локальные из `uses` — имена уникальны в функции.
- Область квантора: переменная видна только в его теле; её имя не должно совпадать с видимыми в этом месте именами
  (`requires` — параметры, `ensures` — параметры и возвраты, тело функции — всё).
- Видимость по частям функции: в `requires` — только параметры; в `ensures` — параметры и возвращаемые значения;
  в теле (включая `invariant`, `assert`, `assume`) — всё; в формуле — только её параметры.
- Переменные и функции — разные пространства имён: `x(x: int) ... r = x(x);` допустимо.

**Типы.** Арифметика, унарный минус, сравнения и индексы требуют `int`; индексируется только `int[]`; присваивание
требует совпадения типов; вызовы проверяют число и типы аргументов; функция с несколькими результатами допустима
только в кортежном присваивании, где число целей должно совпадать с числом результатов.

**Присваивания.** Параметры доступны только для чтения (в том числе через `a[i] = v`); цели кортежного
присваивания не повторяются.

**Использование до присваивания.** Возвраты и локальные нельзя читать в точке, где они могут быть ещё не
присвоены (параметры инициализированы всегда). После `if` присвоено то, что присвоено в обеих ветках; присваивания
в теле `while` после цикла не учитываются (тело может не выполниться). `ensures` на это не проверяется.

**Константы.** В исполняемом коде целая константа должна помещаться в 32 бита (`-2147483648` допустимо);
в предикатах (`requires`, `ensures`, `invariant`, `assert`, `assume`, формулы) целые математические и
диапазон не проверяется.

**Вывод типов локальных (бонус).** У локальной без аннотации тип в таблице переменных сначала пустой; при обходе тела
его записывает первое корректное присваивание (или контекст: арифметика, индексы, аргументы, `a[i] = v` → `int[]`),
дальше тип только сверяется. Противоречие — ошибка с указанием, где тип был выведен; если тип не вывести (переменной
ничего не присваивается) — ошибка `не удалось вывести тип локальной переменной 'x': укажите тип явно`. Подробно —
в [`REPORT.md`](REPORT.md).

## Сообщения об ошибках

Формат: `<файл>:<строка>:<столбец>: ошибка: <сообщение>` (как в HW2), позиция — первый токен узла, к которому
относится ошибка (имя, операнд, аргумент, цель присваивания). Ошибки сортируются по позиции.

| Сообщение | Когда |
|---|---|
| `неизвестное имя 'x'` | переменная не объявлена (или квантор вне своего тела) |
| `'f' — функция, а не переменная` | имя функции/формулы использовано как переменная |
| `неизвестная функция 'g'` / `неизвестная формула 'p'` | вызов или ссылка на необъявленное имя |
| `повторное объявление 'x': уже объявлено в L:C` | повтор функции/формулы, параметра/возврата/локальной, переменной квантора |
| `'r' недоступно в requires: там видны только параметры` | возврат или локальная в `requires` |
| `'t' недоступно в ensures: там видны только параметры и возвращаемые значения` | локальная в `ensures` |
| `'p' — формула; формулы используются только в предикатах` | формула вызвана в выражении |
| `'f' — функция, а не формула` | функция там, где ожидается ссылка на формулу |
| `функция 'g' ожидает 2 аргумента, передано 3` | неверное число аргументов (и `формула 'p' ...`) |
| `аргумент 1 функции 'g': ожидается int, получено int[]` | неверный тип аргумента |
| `функция 'd' возвращает 2 значения; в выражении допустим только вызов с одним результатом` | кортеж в выражении |
| `функция 'd' возвращает 2 значения, а в левой части 3 переменные` | несовпадение числа целей |
| `переменная 'q' повторяется в левой части` | повтор цели кортежного присваивания |
| `параметр 'x' доступен только для чтения` | присваивание параметру |
| `присваивание 'r': переменная имеет тип int, значение — int[]` | несовпадение типов в присваивании |
| `операнд '+': ожидается int, получено int[]` | арифметика / унарный минус над массивом |
| `сравнение '<': ожидается int, получено int[]` | сравнение не-`int` |
| `обращение по индексу к 'x': ожидается int[], получено int` | индексация не-массива |
| `обновление элемента 'r': ожидается int[], получено int` | `r[i] = v` для не-массива |
| `индекс массива: ожидается int, получено int[]` | индекс не `int` |
| `значение элемента массива: ожидается int, получено int[]` | `a[i] = v` с `v` не `int` |
| `переменная 't' используется до присваивания` | чтение до присваивания (одно сообщение на переменную) |
| `константа 2147483648 не помещается в int (32 бита)` | слишком большая константа в коде |
| `не удалось вывести тип локальной переменной 'x': укажите тип явно` | вывод невозможен |
| `... получено int[] (тип 't' выведен в 6:7)` | противоречие при выводе: где был выведен тип |

**Восстановление.** После ошибки выражение получает «ошибочный» тип, совместимый со всем, поэтому одна ошибка не
порождает каскад (`(y + 1) * length(y)` с неизвестным `y` — по сообщению на каждое вхождение `y`, без ошибок про
`+` и `length`). Аргументы неизвестной функции всё равно проверяются. При повторном объявлении в таблице
остаётся первое, а тело повторной функции тоже проверяется.

## Отклонения от `funny.ru.md` и задания

1. Чтение неинициализированной переменной в `funny.ru.md` — «неопределено»; здесь это ошибка компиляции (проверка
   «использование до присваивания» — так в Funny выражается пункт задания «использование до объявления»: все
   переменные объявляются в заголовке функции, поэтому «до объявления» имя использовать нельзя синтаксически).
2. Сравнения (включая `==`, `!=`) требуют `int` — как в разделе «Вывод типов» `funny.ru.md`; сравнивать массивы
   целиком нельзя.
3. Функции и формулы — одно глобальное пространство имён; переменные — отдельное.
4. `set` — не функция API: пользовательский вызов `set(...)` без своего объявления — `неизвестная функция 'set'`.
5. Тип локальной выводится по ходу обхода тела в порядке текста: первое ограничение (присваивание или
   контекст) фиксирует тип. В корректной программе первым всегда идёт присваивание, потому что чтение до
   присваивания — ошибка.
6. При синтаксических ошибках семантический анализ не запускается.

## Тесты

```
tests/positive/NN_имя.funny   программа без ошибок
tests/positive/NN_имя.ast     эталон аннотированного дерева (вывод funnycheck)
tests/positive/NN_имя.json    эталон JSON (01_sum, 04_array_update)
tests/positive/NN_имя.sym     эталон таблиц символов (03_divmod_tuple, 07_infer_chain)
tests/negative/NN_имя.funny   программа с семантическими ошибками
tests/negative/NN_имя.err     точный ожидаемый stderr (метка — имя файла)
```

- **Позитивные (10):** сумма массива (вывод `i`, `invariant`, `length`), max с `if`/`else`, кортежное присваивание
  (вывод `q, r` из результатов), обновление массива, формулы и кванторы (в т. ч. над `int[]`), рекурсия и вызовы
  функций, объявленных ниже, цепочки вывода (литерал → переменная → вызов → `length` → массив), области видимости
  и пространства имён, `assert`/`assume`, присваивание в обеих ветках `if`.
- **Негативные (35):** неизвестные имя/функция/формула, повторные объявления (функции, формула+функция,
  параметр/возврат, локальная, переменная квантора), возврат в `requires`, локальная в `ensures`, квантор вне
  тела, присваивание параметру (обычное и `a[i] = v`), несовпадение типов в присваивании, арифметика и сравнения
  над массивами, индексация не-массива и индекс не `int`, число и типы аргументов (в т. ч. `length`), кортеж в
  выражении, число целей кортежа, повтор цели, формула в выражении, функция вместо формулы, функция как
  переменная, использование до присваивания (просто, после одной ветки `if`, после `while`), противоречия вывода
  (присваиванием и использованием), невозможность вывода, диапазон констант, ошибки в нескольких функциях сразу,
  вывод по первому *корректному* присваиванию.
- **Модульные (gtest, 43):** таблицы символов и видимость (`SymbolTest`), типизация и сообщения (`TypeTest`), вывод
  типов (`InferTest`), использование до присваивания (`InitTest`), формат
  дерева и JSON (`PrintTest`), эталоны (`SnapshotTest`), мутации (`RobustTest`: в каждой позитивной программе
  каждое имя заменяется на `zz`/`a`/`length`/`sum`, каждый `int` — на `int[]`, каждое число — на 99999999999;
  проверяются отсутствие падений, корректность позиций и порядок ошибок).

`funnycheck test --bless` перезаписывает эталоны фактическим выводом (`.json`/`.sym` — только существующие;
позитивные тесты с ошибками не перезаписываются). После `--bless` эталоны нужно просмотреть глазами.
