# Отчёт по HW3: семантические проверки и типы

## 1. Типы

```
T   ::= int | int[]                    типы значений (переменные, параметры, выражения)
B   ::= bool                           тип условий и предикатов
F   ::= (T1, ..., Tn) -> R             функция: R = T или кортеж (T1, ..., Tk), k >= 2
      | (T1, ..., Tn) -> bool          формула
```

`bool` не бывает типом переменной (в Funny нет булевых переменных), а функции не бывают значениями — поэтому
выражения имеют только типы `int`, `int[]` или (один случай) кортеж. В C++ это `ExprType = std::vector<TypeKind>`.
Во время проверки используется внутренний тип `Ty`: `int`, `int[]`, «тип локальной без аннотации» (ссылка на её
строку в таблице переменных функции) или «ошибка» (совместима с чем угодно, чтобы не было каскада сообщений).

## 2. Правила типизации

Γ — видимые переменные (с учётом части функции, см. §3), Σ — глобальная таблица.

| Конструкция | Требование | Тип |
|---|---|---|
| `n` (число) | в коде `n ≤ 2^31−1` (`-n`: `n ≤ 2^31`); в предикатах — без ограничения | `int` |
| `x` | `x ∈ Γ`; возврат/локальная присвоены (в теле) | Γ(x) |
| `a[e]` | `a : int[]`, `e : int` | `int` |
| `-e` | `e : int` | `int` |
| `e1 op e2`, `op ∈ + - * /` | `e1 : int`, `e2 : int` | `int` |
| `f(e1..en)` | `f ∈ Σ` — функция с n параметрами, `ei : Pi`, ровно один результат | результат `f` |
| `length(e)` | `e : int[]` | `int` |
| `e1 cmp e2` | `e1 : int`, `e2 : int` | `bool` |
| `not c`, `c1 and/or/-> c2` | операнды `bool` (гарантирует грамматика) | `bool` |
| `forall/exists (x: T \| p)` | имя `x` не занято в Γ; `p` проверяется в Γ + {x: T} | `bool` |
| `p(e1..en)` (ссылка на формулу) | `p ∈ Σ` — формула с n параметрами, `ei : Pi` | `bool` |

| Оператор | Требование |
|---|---|
| `x = e;` | `x` — возврат или локальная (не параметр); `typeof(x) ~ typeof(e)`; `e` — не кортеж |
| `a[i] = v;` (= `a = set(a, i, v)`) | `a : int[]` (и `a` присвоена), `i : int`, `v : int`; `a` — не параметр |
| `x1, ..., xk = f(...);` | `f` — функция с k результатами, `xi ~ Ri`, цели различны и не параметры |
| `if (c) S1 else S2`, `while (c) invariant p S` | `c`, `p` — корректные условие/предикат |
| `assert p;`, `assume p;` | `p` — корректный предикат |

`~` — совпадение типов: для известных типов — точное равенство; если тип локальной ещё не выведен, он выводится
(§4). Приведений и перегрузок нет.

## 3. Таблицы символов и области видимости

- **Глобальная** (`GlobalScope`, `Symbols.h`): `length : (int[]) -> int` и все функции/формулы модуля. Строится до
  проверки тел, поэтому порядок объявлений не важен (рекурсия, взаимная рекурсия, вызов функции, объявленной
  ниже). Повторное имя — ошибка; в таблице остаётся первое объявление.
- **Функции**: параметры (`param`), возвраты (`return`), локальные (`local`). Имена уникальны в функции.
- **Кванторы**: стек областей; переменная (`bound`) видна только в теле квантора.
- **Видимость по частям функции:**

| Часть | Видно |
|---|---|
| `requires` | параметры + кванторы |
| `ensures` | параметры, возвраты + кванторы |
| тело, `invariant`, `assert`, `assume` | всё |
| тело формулы | параметры формулы + кванторы |

Имя, которое объявлено в функции, но не видно в этой части, даёт отдельное сообщение (`'r' недоступно в
requires: ...`), а не «неизвестное имя». Результат разрешения имён сохраняется в AST (`VarRef::kind`) и
печатается командой `funnycheck symbols`.

## 4. Вывод типов локальных (бонус)

Тип хранится в той же таблице переменных функции (`VarSymbol` в `Checker.h`): у локальной без аннотации поле
`type` сначала пустое, `inferred = true`, а `inferred_at` — позиция, где тип выведен.

Тело функции обходится один раз в порядке текста. Где тип переменной `t` без аннотации обязан быть известен:

| Ситуация | Действие |
|---|---|
| `t = e`, тип `e` известен | тип `t` пуст — записать тип `e` и позицию; уже есть и другой — ошибка |
| `t` в контексте, где нужен тип T (операнд, индекс, аргумент, `t[i] = v` → `int[]`) | тип пуст — записать T; другой — ошибка |
| `e` с ошибкой | ничего: тип выводится по первому **корректному** присваиванию |
| `t = u`, тип не известен ни у `t`, ни у `u` | ничего (так бывает, только если `u` читается до присваивания — это уже ошибка) |

В корректной программе любое чтение переменной идёт после присваивания ей (§5), поэтому тип фиксирует первое
присваивание, а всё остальное только сверяется с ним.

В конце функции выведенный тип переносится в AST (`LocalDef::type`, `inferred = true`); если тип так и не появился —
ошибка `не удалось вывести тип локальной переменной 'x'`. Сообщение о противоречии указывает, где тип был выведен:
`присваивание 't': переменная имеет тип int (тип 't' выведен в 2:7), значение — int[]`.

Примеры:

```
uses a, b, c, len, arr     a = 1; b = a; c = b * a;       a, b, c : int
                           len = length(v);               len : int
                           arr = make(c);                 arr : int[]   (make : (int) -> int[])
uses q, r                  q, r = divmod(x, 7);           q, r : int    (из кортежа результатов)
uses t                     t = v; t[0] = 42;              t : int[]
uses t                     t = 1; t = a;                  ошибка: t уже int (выведен в ...)
uses t                     (не присваивается)             ошибка: не удалось вывести тип
```

## 5. Использование до присваивания

Анализ «определённого присваивания» по структурному AST: множество точно присвоенных возвратов и локальных
(параметры присвоены всегда).

- присваивание (в т. ч. кортежное) добавляет цели — после вычисления правой части;
- `if`: на выходе — пересечение множеств двух веток (нет `else` — пустая ветка);
- `while`: условие и `invariant` проверяются при входе; присваивания в теле после цикла не учитываются;
- чтение не присвоенной переменной — ошибка; после сообщения переменная считается присвоенной (одно сообщение
  на переменную);
- `requires`/`ensures` и формулы не проверяются (это спецификация, а не исполнение).

## 6. Аннотированный AST

Тип каждого выражения, вид каждой переменной и выведенные типы локальных хранятся прямо в узлах AST HW2
(`Expr::type`, `VarRef::kind`, `LocalDef::type`/`inferred`) — следующему этапу (IR) не нужны отдельные таблицы.
Формат дерева и JSON — [`docs/ast.md`](docs/ast.md).

## 7. Ограничения

- Только типы Funny: `int`, `int[]` (одномерные массивы), `bool` в условиях; нет перегрузок, приведений,
  пользовательских типов и `string`. Функции не являются значениями.
- Сравнения (в т. ч. `==`) — только над `int`; массивы целиком сравнивать нельзя.
- Не проверяется, что все возвращаемые значения присвоены к концу функции, и не проверяется инициализация в
  `ensures`.
- Анализ присваивания консервативен: не учитывает значения условий (`if (true) t = 1;` не считается присвоением
  на всех путях) и не заходит в цикл повторно.
- Деление на ноль и выход за границы массива не ищутся статически (по `funny.ru.md` это исключения времени
  выполнения).
- Тип локальной выводится только внутри её функции (локальные не видны снаружи) и только из int/int[]; полиморфизма
  нет.
- Рекурсия формул не запрещается и не анализируется.
- При синтаксических ошибках семантический анализ не выполняется.
