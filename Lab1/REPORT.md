# Отчёт по HW1: регулярные выражения → ДКА → минимизация

## 1. Регулярные выражения токенов

Список вшит в `RegexLIB/src/TokenSpec.cpp`; порядок = приоритет (при равной длине совпадения побеждает правило выше).

| Токены | Регулярное выражение | Флаг |
|---|---|---|
| `KW_FUNCTION` … `KW_EXISTS` (20 шт.) | `function`, `returns`, `requires`, `ensures`, `uses`, `while`, `if`, `else`, `assert`, `assume`, `invariant`, `length`, `int`, `true`, `false`, `not`, `and`, `or`, `forall`, `exists` | |
| `IDENT` | `[A-Za-z][A-Za-z0-9_]*` | |
| `INT` | `0\|[1-9][0-9]*` | |
| `BAD_INT` | `0[0-9]+` | error |
| `WS` | `[ \t\r\n]+` | skip |
| `COMMENT` | `//[^\n]*` | skip |
| `EQ NE LE GE ARROW FAT_ARROW` | `==` `!=` `<=` `>=` `->` `=>` | |
| `LT GT ASSIGN PLUS MINUS STAR SLASH` | `<` `>` `=` `\+` `-` `\*` `/` | |
| `LPAREN RPAREN LBRACKET RBRACKET LBRACE RBRACE` | `\(` `\)` `\[` `\]` `{` `}` | |
| `COMMA SEMICOLON COLON PIPE` | `,` `;` `:` `\|` | |

Решения:

- **Ключевые слова** стоят раньше `IDENT`, поэтому `while` → `KW_WHILE`, а `whilex`, `while_`, `If` → `IDENT`
  (максимальное совпадение + приоритет).
- **Идентификатор** по спецификации Funny начинается с латинской буквы; `_` допускается внутри и в конце
  (`a_b`, `a_`). `_x` — ошибка (`ERROR("_")`, затем `IDENT("x")`). Если нужно разрешить `_` в начале, в
  `TokenSpec.cpp` достаточно заменить класс на `[A-Za-z_]`.
- **`00`, `01`**: без отдельного правила максимальное совпадение разбило бы `01` на `INT(0) INT(1)`.
  Правило `BAD_INT` с флагом `error` забирает всю цифровую последовательность с ведущим нулём, и она
  выдаётся как одна ошибка.
- **`:`, `|`, `->`, `=>`** есть в грамматике Funny (типы, кванторы, импликация, формулы), поэтому они тоже токены.
  `int[]` разбирается как `KW_INT LBRACKET RBRACKET`, и собирает его уже парсер.
- `/` против `//`: `a/b` → `SLASH`, `a//b` → комментарий (максимальное совпадение).

## 2. Размеры автоматов

| Стадия | Состояний | Примечание |
|---|---|---|
| НКА (Томпсон) | **301** | 309 рёбер |
| ДКА (построение подмножеств) | **126** | 125 + ловушка |
| Минимальный ДКА (Хопкрофт) | **123** | 122 + ловушка |
| Экспортируемая таблица | 123 × 46 | 256 байтов сжаты в 46 классов, 5658 ячеек |

При минимизации склеились три пары состояний, у каждого токена из пар разные "первое повторение"
и "последующие повторения", которые ведут себя одинаково:

- `INT`: после `[1-9]` и после `[1-9][0-9]+`;
- `IDENT`: после первой буквы (если это не префикс ключевого слова) и после `[A-Za-z0-9_]` в продолжении;
- `COMMENT`: сразу после `//` и после `//` + символы.

Остальной ДКА уже минимален: префиксы ключевых слов (`i`, `in`, `int` …) все различимы, и состояния с
разными токенами Хопкрофт не склеивает по построению (начальное разбиение — по токену).

Проверки корректности (`RegexLIB/test/AutomataTest.cpp`):

- для всех строк длины ≤ 4 над алфавитом `if0_1=!/ \n\xFF` и для 20 000 случайных строк результат
  прямой симуляции НКА совпадает с ДКА и с минимальным ДКА;
- независимая минимизация алгоритмом Мура даёт то же число состояний (и на ДКА Funny, и на 8 других регулярках);
- все состояния минимального ДКА достижимы, ловушка непринимающая и замкнута;
- учебный пример `(a|b)*abb` → 4 состояния + ловушка.

## 3. Ловушка

Ловушка — состояние **0** минимального ДКА (старт — **1**): оно не принимающее, все переходы
ведут в него же. При построении подмножеств это пустое множество состояний НКА, поэтому ДКА
сразу полный: переход определён для каждого состояния и каждого из 128 символов ASCII.
В экспортируемой таблице для всех байтов 128..255 заведён отдельный класс, и из любого состояния
он ведёт в ловушку.

В ловушку попадают:

- любой не-ASCII байт (`ж`, `→`, эмодзи, `\xFF`), в том числе внутри комментария
  (алфавит языка — ASCII);
- ASCII-символы, с которых не начинается ни один токен: `@ # $ % ^ & ? . ~ ' " \` \\`, управляющие символы, `\f`, `\v`, DEL;
- продолжение, которое не может стать токеном (`!x`, `1\xFF`).

Поведение лексера: как только автомат попадает в ловушку, лексер возвращается к последнему
принимающему состоянию. Если такого не было, выдаётся `ERROR` на один символ (UTF-8
последовательность забирается целиком, так что `ж` даёт одну ошибку, а не две), и разбор
продолжается дальше. `!` сам по себе — `REJECT` (это префикс `!=`), в лексере он тоже `ERROR`.

## 4. Тесты

- `tests/cases.txt` — **182** табличных теста (`match`: вся строка через ДКА, `lex`: разбиение на токены):
  пустая строка; пробелы, табы, CR, LF, CRLF; `0`, `00`, `01`, `007`; идентификаторы с `_`;
  все 20 ключевых слов, их префиксы и расширения, регистр; все разделители и операторы,
  а также максимальное совпадение на них (`===`, `<==`, `-->`); комментарии до конца строки
  (LF/CRLF, `/` против `//`, `/* */` комментарием не считается); не-ASCII (2-, 3-, 4-байтные UTF-8,
  одиночные байты `\x80`, `\xFF`) и непокрытые ASCII-символы; фрагменты программ на Funny.
  Результаты прогона: `artifacts/test_results.txt` (182/182 PASS).
- `LexerTest.EverySingleByteIsCovered` — каждый из 256 байтов по отдельности: ожидаемый токен или ловушка.
- `LexerTest.AlwaysProgressesAndCoversInput` — на случайных байтах лексер всегда продвигается,
  а склеенные лексемы дают исходный вход.
- `GeneratedTableTest` — `artifacts/funny_lexer_table.h` совпадает с библиотекой таблица в таблицу
  и токен в токен; `static_assert` проверяют, что он работает в `constexpr`.
