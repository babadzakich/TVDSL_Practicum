# HW2. PEG-парсер Funny поверх лексера HW1 — дизайн

Дата: 2026-10-19. Каталог проекта: `Lab2/` (репозиторий `tvpol`, рядом `Lab1/` — лексер HW1).

## 1. Зачем

Домашнее задание HW2: синтаксический анализатор языка Funny (описание языка — `Lab2/docs/funny.ru.md`, текст
дан пользователем; это источник истины, грамматика §5 — его PEG-пересказ, расхождения перечислены в §10), интегрированный с лексером из HW1, с выводом AST и
диагностикой ошибок с позициями. AST должен годиться для следующих HW и проекта (T0/T1).

Задание предлагает LL(1) (рекурсивный спуск) или LR/SLR. **Решение пользователя: PEG**, написанный вручную,
работающий над потоком токенов лексера HW1. Это отклонение от задания, его надо явно обосновать в README.
Обоснование (для README): в грамматике Funny есть места, где LL(1) требует переписывания/факторизации, а PEG
решает их упорядоченным выбором с откатом:

- функция и формула на уровне модуля обе начинаются с `ident "(" params ")"` и различаются только после `)`
  (`requires`/`returns` против `=>`);
- в условиях `(a+b) > c` (скобки выражения) против `(x > 0)` (скобки условия);
- в предикатах `f(x)` (ссылка на формулу) против `f(x) == 3` (сравнение с вызовом).

Левая рекурсия выражений заменяется повторением, приоритеты — уровнями правил.

## 5. Грамматика (PEG над токенами)

Терминалы — имена `TokenKind` лексера; в кавычках — их лексемы для читаемости. Финальная версия грамматики
сдаётся отдельным файлом `Lab2/grammar.peg` в этой же нотации (с комментариями-ссылками на правила
`funny.ru.md`).

```peg
Module       <- Decl+ EOF                       # пустой ввод — ошибка
Decl         <- Formula / Function              # Formula различается по '=>' после ')'
Formula      <- IDENT '(' Params? ')' '=>' Predicate
Function     <- IDENT '(' Params? ')'
                ('requires' Predicate)?
                'returns' VarDef (',' VarDef)*
                ('ensures' Predicate)?
                ('uses' LocalDef (',' LocalDef)*)?
                Statement
Params       <- VarDef (',' VarDef)*
VarDef       <- IDENT ':' Type
LocalDef     <- IDENT (':' Type)?
Type         <- 'int' ('[' ']')?                # int[] приходит тремя токенами KW_INT LBRACKET RBRACKET

Statement    <- Block / If / While / Assert / Assume / Assignment
Block        <- '{' Statement* '}'
If           <- 'if' '(' Condition ')' Statement ('else' Statement)?
While        <- 'while' '(' Condition ')' ('invariant' Predicate)? Statement
Assert       <- 'assert' Predicate ';'
Assume       <- 'assume' Predicate ';'
Assignment   <- TupleAssign / ArrayAssign / SimpleAssign
TupleAssign  <- IDENT (',' IDENT)+ '=' Call ';' # >= 2 целей; `x = f(y);` — это SimpleAssign
ArrayAssign  <- IDENT '[' Expr ']' '=' Expr ';' # сахар, см. §6.2
SimpleAssign <- IDENT '=' Expr ';'

Expr         <- Term (('+' / '-') Term)*        # левоассоциативно
Term         <- Unary (('*' / '/') Unary)*      # левоассоциативно
Unary        <- '-' Unary / Primary             # унарный минус связывает сильнее всех
Primary      <- Call / ArrayAccess / INT / IDENT / '(' Expr ')'
Call         <- (IDENT / 'length') '(' (Expr (',' Expr)*)? ')'   # length — токен KW_LENGTH
ArrayAccess  <- IDENT '[' Expr ']'

Condition    <- COr ('->' Condition)?           # импликация правоассоциативна, самый низкий приоритет
COr          <- CAnd ('or' CAnd)*
CAnd         <- CNot ('and' CNot)*
CNot         <- 'not' CNot / CAtom
CAtom        <- 'true' / 'false' / Comparison / '(' Condition ')'   # Comparison раньше скобок: (a+b) > c

Predicate    <- POr
POr          <- PAnd ('or' PAnd)*
PAnd         <- PNot ('and' PNot)*
PNot         <- 'not' PNot / PAtom
PAtom        <- Quantifier / 'true' / 'false' / Comparison / FormulaRef / '(' Predicate ')'
Quantifier   <- ('forall' / 'exists') '(' VarDef '|' Predicate ')'
FormulaRef   <- IDENT '(' (Expr (',' Expr)*)? ')'                    # после Comparison: f(x) == 3 vs f(x)

Comparison   <- Expr CmpOp Expr
CmpOp        <- '==' / '!=' / '>=' / '<=' / '>' / '<'
```

Приоритеты (фиксируются в `grammar.peg` и README):

| Уровень (от слабого к сильному) | Операторы | Ассоциативность |
|---|---|---|
| условия | `->` | правая |
| | `or` | левая |
| | `and` | левая |
| | `not` | префикс |
| сравнения | `== != >= <= > <` | не ассоциативны (одно на сравнение) |
| выражения | `+ -` | левая |
| | `* /` | левая |
| | унарный `-` | префикс |

Условия (`if`/`while`) и предикаты (`requires`/`ensures`/`invariant`/`assert`/`assume`/формулы) — **разные
правила, строго как в `funny.ru.md`**: в условиях есть `->`, нет кванторов и ссылок на формулы; в предикатах
наоборот. Асимметрия сохраняется и документируется.

## 6. AST

### 6.1 Общие требования

- Публичный заголовок AST в `ParserLIB/Include/` — это API для следующих HW; формат JSON описан отдельным
  документом `Lab2/docs/ast.md` (виды узлов, поля, пример).
- У **каждого** узла есть позиция начала: `line`, `col` (1-based) и байтовое смещение `offset`.
- Узлы (минимальный набор): `Module`, `Function` (name, params, requires?, returns, ensures?, uses, body),
  `Formula` (name, params, body), `VarDef` (name, type), `LocalDef` (name, type?), `Type` (`int`/`int[]`);
  операторы `Block`, `If`, `While` (cond, invariant?, body), `Assert`, `Assume`, `Assign` (targets[], value,
  sugar-флаг), `TupleAssign` (targets[], call); выражения `IntLit` (лексема как в тексте), `Var`, `ArrayAccess`,
  `Call`, `Unary`, `Binary` (op); условия/предикаты `BoolLit`, `Compare` (op), `Not`, `And`, `Or`, `Implies`,
  `Quantifier` (forall/exists, var, body), `FormulaRef`.
- Отсутствующие `requires`/`ensures`/`invariant` в AST — отсутствуют (null в JSON), а не подставленные
  умолчания `true`/`false`: умолчания — семантика следующего этапа. *(Моё решение.)*

### 6.2 Обновление массива — сахар *(моё решение; пользователь вопрос не закрыл)*

`a[i] = v;` парсер сразу превращает в `Assign{targets:[a], value: Call{"set", [Var a, i, v]}}` с пометкой, что
это сахар (поле `sugar: "array_update"` в JSON; позиция — позиция `a`). Отдельного узла обновления массива нет.
`a[i][j] = v` грамматикой не допускается (ArrayAccess — `varName "[" expr "]"`, массивы одномерные) —
отклонение от примера в `funny.ru.md`, документируется.

### 6.3 Вывод

- Текстовое дерево с отступами (детерминированное — используется в snapshot-тестах), например:

  ```
  Module
    Function sum @1:1
      param a: int[] @1:5
      returns s: int @1:22
      ...
  ```

- JSON — по флагу `--json`; схема в `docs/ast.md`.
- Точный вид текстового дерева и имена JSON-полей — на усмотрение исполнителя, но после фиксации они
  документируются и покрываются эталонами.

## 7. Ошибки

### 7.1 Формат

`<файл>:<строка>:<столбец>: ошибка: <сообщение>` в stderr (`<stdin>`, если читаем stdin). Столбец — номер байта
в строке (алфавит Funny — ASCII, UTF-8 не поддерживается), 1-based, таб = 1 столбец. Байты вне печатного ASCII в
сообщениях выводятся как `\xHH`.

Сообщения — на русском, токены показываются лексемой в кавычках (`';'`, `'=='`), классы — словами
(`идентификатор`, `число`, `конец файла`). Для нетерминалов можно метки (`ожидалось выражение` вместо списка из
шести токенов) — на усмотрение исполнителя, лишь бы читалось.

Примеры (ориентиры для эталонов, точная формулировка фиксируется при реализации):

- `1:1: ошибка: ожидается объявление функции или формулы, найден конец файла`
- `2:12: ошибка: ожидается ')', найдено '{'`
- `9:1: ошибка: ожидается '}' (для '{' в 3:5), найден конец файла`
- `4:7: ошибка: некорректное число '007': ведущие нули не допускаются`, `4:5: ошибка: недопустимый символ '@'`

Шаблон — «ожидается X, найдено 'Y'» («ожидается» согласуется с любым родом метки). Продолжения циклов бинарных
операторов (`+ - * /`, `and`, `or`, `->`), закрывающая `}` в цикле блока и синтаксические предикаты в список
ожидаемого **не попадают** — иначе почти каждое сообщение начиналось бы с перечня операторов. *(Моё решение.)*

### 7.2 Синтаксические ошибки

Механизм «самая дальняя ошибка»: при каждой неудаче сопоставления терминала запоминается позиция; если она
дальше текущей максимальной — множество ожидаемых сбрасывается, если равна — пополняется. Сообщение строится
по самой дальней позиции, когда разбор окончательно не смог продолжиться.

### 7.3 Восстановление

- Ошибки, обнаруженные внутри альтернативы, от которой PEG потом откатился, **не должны попадать** в
  диагностику. Восстановление выполняется только в «зафиксированных» местах, где альтернатив уже нет: как
  минимум (а) уровень модуля — между объявлениями, (б) внутри блока — между операторами. Выбор Formula/Function
  можно сделать детерминированным синтаксическим предикатом (`&(IDENT '(' Params? ')' '=>')`), чтобы тело
  функции разбиралось уже в зафиксированном контексте.
- В блоке: при неудаче оператора — сообщить, пропустить токены до `;` (включительно) или до `}` текущего уровня
  вложенности (с учётом парных скобок), продолжить. На уровне модуля: пропустить до начала следующего
  объявления (`IDENT '('` на нулевой глубине скобок) или до конца файла.
- Гарантия завершения: каждое восстановление поглощает ≥ 1 токен; при EOF разбор заканчивается.
- Критерий качества: файл с тремя ошибками в трёх разных функциях даёт ровно три сообщения.

### 7.4 Ошибки лексера *(моё решение)*

Токены `ERROR` (символ в ловушке, например `@`) и `BAD_INT` (`007`) сообщаются как ошибки с позицией.

- `BAD_INT` дальше разбирается как число — второй ошибки нет.
- `ERROR` остаётся в потоке токеном-заглушкой, который не совпадает ни с одним терминалом. Синтаксическая ошибка,
  чья позиция совпадает с позицией `ERROR`-токена, **подавляется** (лексической достаточно); восстановление
  идёт обычным путём. Итого `x = @;` даёт ровно одно сообщение.
- Подряд идущие `ERROR`-токены (без пробелов между ними) склеиваются в одно сообщение
  (`недопустимые символы '…'`).
- Алфавит Funny — ASCII, **в том числе в комментариях** (решение HW1: `Lab1/REPORT.md`, `Lab1/tests/cases.txt`).
  Не-ASCII в комментарии — лексическая ошибка; таблицы лексера не меняем. Слой токенов Lab2 сообщает её **одним
  сообщением на комментарий** (позиция — первый недопустимый символ) и пропускает остаток строки как комментарий,
  чтобы слова после кириллицы не превращались в лишние токены. *(Моё решение.)*

Наличие любой ошибки → ненулевой код выхода, AST не печатается.

### 7.5 Время

Packrat-мемоизация (правило, позиция) — как минимум для правил с откатом (`Expr`, `Condition`, `Predicate`,
`Comparison` и их атомов), чтобы время было линейным от числа токенов. Как именно мемоизировать — на усмотрение
исполнителя; проверяется тестами из §9.3.

## 9. Тесты

Всё запускается через `ctest` (gtest-бинарь + `funnyparse test`), как в Lab1.

### 9.1 Позитивные

Программы, покрывающие каждую конструкцию; эталон — текстовое дерево (`.ast`), часть — JSON. Минимум:
сумма массива (`while` + `invariant`), max с `if`/`else`, кортежное присваивание из вызова, обновление массива
(сахар), формулы и кванторы в `ensures`, ссылки на формулы, `uses` с типами и без, вложенные блоки, `assert`/
`assume`, комментарии (ASCII), опущенные `requires`/`ensures`, несколько функций и формул в модуле,
`length(a)`. Плюс unit-тесты на приоритеты и ассоциативность (`1 - 2 - 3`, `-a * b`, `a -> b -> c`,
`not a and b or c`) и на корректность позиций.

### 9.2 Негативные (утверждено пользователем)

Каждый — `tests/negative/NN_имя.funny` + `.err` с точным ожидаемым текстом.

| Случай | Пример |
|---|---|
| пустой ввод | пустой файл; файл только из комментария |
| незакрытая `(` | `if (x > 0 { ... }` |
| незакрытая `{` | тело функции без `}` — в сообщении позиция открывающей `{` |
| незакрытая `[` | `y = a[i;` |
| лишние токены | `x = 1 2;`; `)` после функции |
| неверный оператор | `x := 1;`, `if (x = 1)`, `x == 1;` |
| ошибки лексера | `x = 007;`, `x = @;` (по одному сообщению); кириллица в комментарии (одно сообщение на комментарий) |
| неполный заголовок | функция без `returns`; параметр без типа `f(x)`; `int[` без `]` |
| пропущенная `;` | после присваивания, `assert`, `assume` |
| неверные конструкции | `else` без `if`; квантор в условии `if`; `->` в `requires` |
| `function` как имя | `function f(...)` — `function` зарезервирован лексером |
| восстановление | три ошибки в трёх функциях → ровно три сообщения |

### 9.3 Незацикливание

- Для каждой позитивной программы — все префиксы по токенам (обрезка на каждом токене): разбор завершается,
  не падает, при ошибке у неё есть позиция. (Префикс может оказаться корректной программой — это не ошибка.)
- Случайные последовательности токенов (фиксированный seed, сотни штук): то же.
- Ограничение времени на весь набор (gtest-тест с таймером или `TIMEOUT` в ctest).

## 10. Отклонения от `funny.ru.md` / задания (в README)

1. PEG вместо LL(1)/LR (обоснование — §1).
2. `function` (и прочие ключевые слова лексера, напр. `length`, `uses`) нельзя использовать как идентификатор;
   `length` разбирается как имя функции в вызове.
3. Кортежное присваивание требует ≥ 2 целей; `x = f(y);` — обычное присваивание с вызовом в выражении.
4. `a[i][j] = v` не поддерживается (одномерные массивы, ArrayAccess с одним индексом).
5. Унарный минус связывает сильнее бинарных операторов (в EBNF `"-" expr` неоднозначен).
6. Сравнения не цепочечные (`a < b < c` — ошибка).
7. Пустой модуль — синтаксическая ошибка.
8. Сахар `a[i] = v` раскрывается в `a = set(a, i, v)` уже в парсере.
9. Не-ASCII символы запрещены и в комментариях (наследуется от лексера HW1).

## 11. Оставлено исполнителю

Внутреннее устройство PEG-движка (комбинаторы или рукописные функции-правила, представление мемо-таблицы),
представление AST в C++ (variant или иерархия классов), точный вид текстового дерева и имена JSON-полей (с
документированием), точные формулировки сообщений, разбиение на файлы, имена namespace'ов.
